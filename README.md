# HolyHelper

Клиентский мод-помощник для режима **Прайм Анархия** сервера HolyWorld
(`mc.holyworld.ru` / `mc.holyworld.me`, Minecraft 1.21.11+, Fabric).

Мод считает то, что игрок обычно держит в голове: где выгоднее сдать ресурс —
Скупцу или на Маркет, сколько осталось до ротации торгов, как ходит курс на Бирже.

## Чего мод не делает

Это не оговорки, а условия, при которых мод вообще имеет право существовать
на сервере с такими правилами:

- **не отправляет ни одного игрового пакета.** Единственный исходящий трафик —
  запрос к официальному `liteapi:feature-control` и GET-запросы к `api.holyworld.me`;
- **не кликает по слотам** и не автоматизирует инвентарь и хранилища;
- **не рендерит сущности**, не рисует миникарту, не трогает анимации и частицы;
- **читает только те окна, которые игрок открыл сам**, и только пока они открыты;
- **вне серверов HolyWorld молчит целиком.**

Каждая функция объявляется серверу при входе через `feature-control`. Попавшая
в блок-лист исчезает из интерфейса полностью, а не просто перестаёт работать.

**На Прайме LiteAPI не поднят** — проверено запуском: сервер даже не объявляет
канал `liteapi:feature-control`. Документация на него лежит в разделе Лайта, и для
Прайма она, похоже, неприменима. Мод это переживает: `FeatureGate` сообщает
«канал не объявлен сервером», считает все функции разрешёнными и работает дальше.
Если канал однажды появится — блок-лист заработает сам, без правок.

## Что уже есть

Этап M1 — каркас и проверка LiteAPI:

| | |
|---|---|
| `liteapi/` | транспорт запрос-ответ поверх Plugin Messaging Channel, корреляция по UUID, таймаут 5 с, лимит 1 запрос в 10 с |
| `liteapi/FeatureGate` | реестр функций мода и блок-лист сервера, мягкая деградация при молчании |
| `board/ScoreboardWatcher` | баланс из сайдбара — без пакетов и без сканирования окон |
| `core/Patterns` | регулярки разбора вынесены в редактируемый `patterns.json`; версия из мода побеждает устаревшую в конфиге |
| `core/Numbers` | разбор чисел, устойчивый к разным разделителям разрядов |
| `scan/BuyerParser` | разбор товаров и множителей Скупца — без единого класса Minecraft, поэтому проверяется тестами |
| `scan/BuyerScanner` | чтение открытого окна: товары опознаются по подсказке, а не по номеру слота |
| `scan/MarketParser` | разбор лотов Маркета, тоже без классов Minecraft |
| `scan/MarketScanner` | витрина: страница, категория, сортировка и лоты |
| `scan/ScreenReader` | единственное место, знающее, как достать содержимое открытого окна |
| `analytics/RotationTimer` | часы обновления ассортимента: из остатка в подсказке считается момент, дальше идут сами |
| `analytics/MultiplierMath` | приводит наблюдаемый множитель к достижимому и отличает округление от второго множителя |
| `store/PriceStore` | наблюдения цен Маркета, переживающие перезаход |
| `rest/HolyApiClient` | GET к `api.holyworld.me` с выдержкой при неудачах |
| `rest/CoinRateTracker` | история курса монеток, медиана и отклонение |
| `hud/HudOverlay` | панель в углу экрана — баланс и оба таймера ротации |
| `command/` | клиентская команда `/holyhelper` |

Панель в углу экрана появилась там, где команда в чате бесполезна: **с открытым окном
Скупца чат не открыть**. Она показывает баланс и сколько осталось до обновления обычных
и особых торгов, и ничего набирать не требует.

Таймеры идут сами. Сервер пишет в подсказке остаток («Обновление товаров через:
6 ч. 12 мин. 47 сек»), а не момент обновления, и этот остаток протухает через секунду
после закрытия окна. Поэтому мод запоминает вычисленный момент — открыл `/b` один раз,
дальше часы тикают без него.

Отрисовка сделана через `HudElementRegistry`: старый `HudRenderCallback` в этой версии
Fabric API помечен `@Deprecated`. Имена классов и методов сверены с исходниками Fabric
и с маппингами yarn 1.21.11, а не взяты по памяти — там, например, `DrawContext`,
хотя сам Fabric API пишет `GuiGraphics`.

## Установка

Мод собирается на GitHub при каждом пуше, поэтому собирать самому не нужно.

1. Откройте вкладку **Actions** в репозитории, выберите верхний зелёный прогон
   ветки и скачайте артефакт **holyhelper** — внутри `holyhelper-0.1.0.jar`.
2. Поставьте **Fabric Loader** для Minecraft 1.21.11, если его ещё нет.
3. Скачайте **Fabric API** для 1.21.11 с
   [Modrinth](https://modrinth.com/mod/fabric-api) — без него мод не запустится.
4. Положите оба файла в папку `mods`.
   В PrismLauncher: правой кнопкой по сборке → **Edit** → **Mods** → **Add file**.
5. Зайдите на `mc.holyworld.ru` и напишите `/holyhelper`.

## Сборка вручную

Если хочется собрать у себя — нужны Java 21 и интернет до `maven.fabricmc.net`:

```bash
./scripts/fetch-fabric-versions.sh   # подставит актуальный yarn
./gradlew build                      # мод появится в build/libs
./gradlew runClient                  # запустит клиент с модом
```

Все версии в `gradle.properties` проставлены и проверены прогоном CI, так что
скрипт нужен только чтобы подтянуть свежий yarn после обновления игры: маппинги
публикуются лишь на `maven.fabricmc.net`. Версия Loom живёт в `build.gradle.kts` —
в блоке `plugins {}` её нельзя вычислить, только записать литералом.

## Проверка

```bash
./gradlew test
```

Тесты разбора построены на строках, снятых со скриншотов живого сервера.
Когда сервер поменяет формулировки, они покраснеют раньше, чем мод соврёт
игроку, и сразу покажут, какую строку править в `patterns.json`.

Фикстуры берутся минимум с двух разных экземпляров одного экрана. Один тултип
Скупца выглядит исчерпывающим, но у обычного товара строка называется
«Цена с множителями», а у особого предложения — «с учётом множителей». По одному
скриншоту это не видно, а цена у всех особых предложений терялась бы молча.

Отдельная защита от тихой поломки — арифметическая самопроверка: у заявки Биржи
`Доступно / Курс` обязано давать `Ожидается`, у окна создания лота
`Вы отдадите / Вы получите` обязано давать `Курс`. Не сошлось — разбор неверен,
запись выбрасывается, а не попадает в базу.

## В игре

```
/holyhelper          состояние: сервер, LiteAPI, баланс, версия паттернов
/holyhelper board    сайдбар так, как его видит мод
/holyhelper buy      товары открытого окна Скупца, дороже сверху
/holyhelper ah       лоты открытой витрины Маркета, дешевле сверху
/holyhelper rate     курс монеток: последняя сделка, медиана за сутки, отклонение
```

### Курс из истории — не то же самое, что курс в окне Биржи

`/v2/prime/coins/trades` отдаёт **совершённые сделки**. В окне Биржи висят **открытые
заявки**, которые ещё никто не принял, и разброс между ними бывает двукратным: за один
заход попадались 11 252 и 6 000 за жетон одновременно. Это разные величины, и путать
их нельзя: одна говорит «за столько менялись», другая — «за столько кто-то готов».

Курс — монетки за один жетон. Сверено с заявкой на Бирже, где то же число стояло
в строке «Курс: 11,252 (за 1 жетон)», и с первой записью истории в тот же момент.

Считается медиана, а не среднее: одна сделка по дикому курсу сдвинет среднее и не
сдвинет медиану. На панели отклонение показывается, только если оно от трёх процентов —
мелкие колебания это шум, а не сигнал.

Опрос идёт раз в минуту и только пока игрок на сервере. При неудаче пауза удваивается
до получаса: явных лимитов у API нет, но есть анти-DDoS, и мод, который долбится
в упавший сервис, — ровно то, из-за чего такие API закрывают.

`buy` показывает последний прочитанный экран, а не текущий, и это не лень, а
единственный рабочий порядок: **с открытым окном чат не открыть**, команду набрать
негде. Поэтому мод читает окно сам, дважды в секунду, пока оно на виду, — а команда
набирается после того, как игрок его закрыл. Возраст снимка печатается всегда, иначе
он однажды соврёт молча.

Товары опознаются по подсказке, а не по номеру слота: раскладка у разделов разная,
а стекло-разделители, кнопка «Назад» и книга справки сидят прямо среди товаров.
Закрытые ячейки товара тем же фильтром отсеиваются сами — объёма приёма у них нет,
но мод считает их отдельно и говорит, сколько этапов нужно до ближайшей.

**Не рассчитывайте, что метка и значение окажутся в одной строке.** Сервер переносит
строку посреди фразы, и делает это непоследовательно — одно и то же поле бывает
и целым, и разорванным. «Прогресс: 0 / 15 000» у ежедневной сделки умещается в строку,
а у этапа «Прогресс:» и «800 / 1 000» разъезжаются на две. То же у множителя
с «Доступно:» и «0 стаков», у цели этапа (три строки) и у закрытой ячейки, где
«после выполнения» кончает одну строку, а «15 Этапов» начинает следующую.

Четыре одинаковые поломки подряд — повод не чинить пятую, а убрать причину. Такие
поля описаны парой «метка + значение», и парсер ищет значение рядом с меткой:
в той же строке либо в одной из двух следующих. Дальше заглядывать нельзя — подхватит
чужое число из соседнего раздела, и на это есть тест. Длинные фразы в регулярках
при этом обязаны помещаться в одну строку подсказки.

### Почему у Маркета нет «снимка рынка»

Витрина постраничная, страниц три десятка, и их число зависит от того, сколько
выставили игроки: было 26, стало 29. Согласованного среза не существует в принципе —
пока листаешь, лоты раскупают и выставляют новые. Поэтому мод хранит не снимок рынка,
а наблюдения отдельных лотов с отметкой времени.

Сортировка при этом важна не меньше самих цен. Игрок выбирает её сам: «сначала
дешёвые», «сначала дорогие», «сначала дешёвые за ед. товара» и так далее. Под первой
первая страница категории — это **дно** рынка, под второй — потолок. Считать по такой
выборке медиану значит соврать, поэтому режим сортировки и категория читаются из меню
(выбранный пункт помечен галочкой) и хранятся рядом с лотами. `/holyhelper ah` печатает
их первой строкой — чтобы по числам было видно, что именно они означают.

### Что мод знает и чего не знает про цены

Мод хранит **наблюдения**, а не «цены рынка»: каждая запись значит «такой лот висел
в такой момент». Отсюда главная оговорка, которая определяет всё остальное:

> самое дешёвое из увиденного — это оценка настоящего дна рынка **сверху**.

Занизить она не может, завысить — запросто: игрок мог не дойти до страницы, где лежит
дешевле, или смотреть под сортировкой «сначала дорогие». Поэтому в списке товаров
Скупца мод пишет «Маркет от N», а не «выгоднее продать на Маркет».

Осторожность нужна и по второй причине: цены несопоставимы напрямую. Скупец платит
сразу и сколько угодно раз в пределах остатка, а лот на Маркете надо выставить,
дождаться покупателя и подвинуться ниже нынешнего дна. Мод показывает числа и
подсвечивает случай, когда на Маркете дороже, — решение остаётся за игроком.

Рядом с ценой всегда печатается, **сколько раз мод это видел**. Одно наблюдение
и десять весят по-разному: единственный лот по дикой цене мог просто висеть и никогда
не продаться. Зелёным подсвечивается только то, что попадалось не один раз, единичное
наблюдение — жёлтым.

Наблюдения копятся сами, пока игрок листает `/ah`, и переживают перезаход. Запись
идёт только когда страница изменилась: витрину мод читает дважды в секунду, и минута
стояния на одном месте иначе превратилась бы в сотню одинаковых записей. На предмет
хранится не больше тридцати наблюдений и не старше недели.

Периоды ротации мод не зашивает в код: сервер печатает их сам в «Полезной информации»
(обычные торги — раз в 6 часов, особые — раз в 8), оттуда и читаются. Так же и с
арифметикой множителей: справка окна «Множители торговли» называет надбавки уровней —
I, II и III дают 5, 10 и 15 процентов — и говорит, что множители разных категорий
**перемножаются**. Товар в двух категориях с уровнями I и II стоит 1,05 × 1,10 = 1,155
базовой цены, а не 1,15. Это готовая формула выгоды для сравнения со Маркетом,
и она приходит от сервера, а не из головы.

Мод видит только начальную и итоговую цену, обе целые, и делит одну на другую.
У дорогих товаров это точно, у дешёвых врёт: ламинария при начальной цене 48
показывала итоговую 51, то есть «×1.06», хотя у соседей в том же списке стояло
честное ×1.05 и множитель был один и тот же. Эти же числа выдают правило округления —
48 × 1,05 = 50,4, а показано 51, значит сервер округляет **вверх**.

Поэтому наблюдаемое отношение приводится к ближайшему достижимому: достижимы только
произведения надбавок, а их сервер называет сам. Вилка при этом шириной в целую
монетку, и чем дешевле товар, тем она шире. Случай «множителя нет» проверяется точным
равенством, а не вилкой: без множителя сервер не пересчитывает цену вовсе. Если
объяснения не нашлось, мод печатает отношение с вопросительным знаком, а не выдаёт
догадку за факт.

Побочная польза: если отношение сошлось с произведением двух надбавок, значит на товар
действуют два множителя сразу — а узнать это иначе нельзя, потому что списки
«Доступные предметы» у разных категорий пересекаются и по содержимому не различаются.

`board` — то, чем чинится разбор. Он печатает строки панели по номерам и отдельной
строкой кодовые точки необычных символов. Пригодилось сразу: слева от подписей
Прайм рисует `U+258C` («▌»), из-за него регулярки с якорем `^` не совпадали,
и баланс молча уезжал в «?». По чату такое не разглядеть, по кодовым точкам — сразу.

Тот же дамп показал ещё две особенности панели Прайма. Справа каждая строка несёт
невидимый хвост из `§` и служебного символа — так сервер делает строки уникальными;
в число он не попадает, потому что класс захвата обрывается на `§`, и это закреплено
тестом. А записи приходят по возрастанию счёта, то есть снизу вверх, поэтому мод
сортирует их как ванильный HUD — по убыванию и не больше пятнадцати.
