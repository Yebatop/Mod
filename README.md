# HolyHelper

Клиентский мод-помощник для режима **Прайм Анархия** сервера HolyWorld
(`mc.holyworld.ru` / `mc.holyworld.me`, Minecraft 1.21.11+, Fabric).

Мод считает то, что игрок обычно держит в голове: где выгоднее сдать ресурс —
Скупцу или на Маркет, сколько осталось до ротации торгов, как ходит курс на Бирже.

## Чего мод не делает

Это не оговорки, а условия, при которых мод вообще имеет право существовать
на сервере с такими правилами:

- **не отправляет ни одного игрового пакета.** Единственный исходящий трафик —
  запрос к официальному `liteapi:feature-control` и GET-запросы к `api.holyworld.me`;
- **не кликает по слотам** и не автоматизирует инвентарь и хранилища;
- **не рендерит сущности**, не рисует миникарту, не трогает анимации и частицы;
- **читает только те окна, которые игрок открыл сам**, и только пока они открыты;
- **вне серверов HolyWorld молчит целиком.**

Каждая функция объявляется серверу при входе через `feature-control`. Попавшая
в блок-лист исчезает из интерфейса полностью, а не просто перестаёт работать.

**На Прайме LiteAPI не поднят** — проверено запуском: сервер даже не объявляет
канал `liteapi:feature-control`. Документация на него лежит в разделе Лайта, и для
Прайма она, похоже, неприменима. Мод это переживает: `FeatureGate` сообщает
«канал не объявлен сервером», считает все функции разрешёнными и работает дальше.
Если канал однажды появится — блок-лист заработает сам, без правок.

## Что уже есть

Этап M1 — каркас и проверка LiteAPI:

| | |
|---|---|
| `liteapi/` | транспорт запрос-ответ поверх Plugin Messaging Channel, корреляция по UUID, таймаут 5 с, лимит 1 запрос в 10 с |
| `liteapi/FeatureGate` | реестр функций мода и блок-лист сервера, мягкая деградация при молчании |
| `board/ScoreboardWatcher` | баланс из сайдбара — без пакетов и без сканирования окон |
| `core/Patterns` | регулярки разбора вынесены в редактируемый `patterns.json`; версия из мода побеждает устаревшую в конфиге |
| `core/Numbers` | разбор чисел, устойчивый к разным разделителям разрядов |
| `scan/BuyerParser` | разбор товаров и множителей Скупца — без единого класса Minecraft, поэтому проверяется тестами |
| `scan/BuyerScanner` | чтение открытого окна: товары опознаются по подсказке, а не по номеру слота |
| `command/` | клиентская команда `/holyhelper` |

Оверлея пока нет намеренно: в свежих версиях Fabric API отрисовка HUD переехала
на новый реестр, и писать это вслепую, до первой удачной сборки, смысла нет.

## Установка

Мод собирается на GitHub при каждом пуше, поэтому собирать самому не нужно.

1. Откройте вкладку **Actions** в репозитории, выберите верхний зелёный прогон
   ветки и скачайте артефакт **holyhelper** — внутри `holyhelper-0.1.0.jar`.
2. Поставьте **Fabric Loader** для Minecraft 1.21.11, если его ещё нет.
3. Скачайте **Fabric API** для 1.21.11 с
   [Modrinth](https://modrinth.com/mod/fabric-api) — без него мод не запустится.
4. Положите оба файла в папку `mods`.
   В PrismLauncher: правой кнопкой по сборке → **Edit** → **Mods** → **Add file**.
5. Зайдите на `mc.holyworld.ru` и напишите `/holyhelper`.

## Сборка вручную

Если хочется собрать у себя — нужны Java 21 и интернет до `maven.fabricmc.net`:

```bash
./scripts/fetch-fabric-versions.sh   # подставит актуальный yarn
./gradlew build                      # мод появится в build/libs
./gradlew runClient                  # запустит клиент с модом
```

Все версии в `gradle.properties` проставлены и проверены прогоном CI, так что
скрипт нужен только чтобы подтянуть свежий yarn после обновления игры: маппинги
публикуются лишь на `maven.fabricmc.net`. Версия Loom живёт в `build.gradle.kts` —
в блоке `plugins {}` её нельзя вычислить, только записать литералом.

## Проверка

```bash
./gradlew test
```

Тесты разбора построены на строках, снятых со скриншотов живого сервера.
Когда сервер поменяет формулировки, они покраснеют раньше, чем мод соврёт
игроку, и сразу покажут, какую строку править в `patterns.json`.

Фикстуры берутся минимум с двух разных экземпляров одного экрана. Один тултип
Скупца выглядит исчерпывающим, но у обычного товара строка называется
«Цена с множителями», а у особого предложения — «с учётом множителей». По одному
скриншоту это не видно, а цена у всех особых предложений терялась бы молча.

Отдельная защита от тихой поломки — арифметическая самопроверка: у заявки Биржи
`Доступно / Курс` обязано давать `Ожидается`, у окна создания лота
`Вы отдадите / Вы получите` обязано давать `Курс`. Не сошлось — разбор неверен,
запись выбрасывается, а не попадает в базу.

## В игре

```
/holyhelper          состояние: сервер, LiteAPI, баланс, версия паттернов
/holyhelper board    сайдбар так, как его видит мод
/holyhelper buy      товары открытого окна Скупца, дороже сверху
```

`buy` показывает последний прочитанный экран, а не текущий, и это не лень, а
единственный рабочий порядок: **с открытым окном чат не открыть**, команду набрать
негде. Поэтому мод читает окно сам, дважды в секунду, пока оно на виду, — а команда
набирается после того, как игрок его закрыл. Возраст снимка печатается всегда, иначе
он однажды соврёт молча.

Товары опознаются по подсказке, а не по номеру слота: раскладка у разделов разная,
а стекло-разделители, кнопка «Назад» и книга справки сидят прямо среди товаров.
Закрытые ячейки товара тем же фильтром отсеиваются сами — объёма приёма у них нет,
но мод считает их отдельно и говорит, сколько этапов нужно до ближайшей.

**Не рассчитывайте, что метка и значение окажутся в одной строке.** Сервер переносит
строку посреди фразы, и делает это непоследовательно — одно и то же поле бывает
и целым, и разорванным. «Прогресс: 0 / 15 000» у ежедневной сделки умещается в строку,
а у этапа «Прогресс:» и «800 / 1 000» разъезжаются на две. То же у множителя
с «Доступно:» и «0 стаков», у цели этапа (три строки) и у закрытой ячейки, где
«после выполнения» кончает одну строку, а «15 Этапов» начинает следующую.

Четыре одинаковые поломки подряд — повод не чинить пятую, а убрать причину. Такие
поля описаны парой «метка + значение», и парсер ищет значение рядом с меткой:
в той же строке либо в одной из двух следующих. Дальше заглядывать нельзя — подхватит
чужое число из соседнего раздела, и на это есть тест. Длинные фразы в регулярках
при этом обязаны помещаться в одну строку подсказки.

Периоды ротации мод не зашивает в код: сервер печатает их сам в «Полезной информации»
(обычные торги — раз в 6 часов, особые — раз в 8), оттуда и читаются.

`board` — то, чем чинится разбор. Он печатает строки панели по номерам и отдельной
строкой кодовые точки необычных символов. Пригодилось сразу: слева от подписей
Прайм рисует `U+258C` («▌»), из-за него регулярки с якорем `^` не совпадали,
и баланс молча уезжал в «?». По чату такое не разглядеть, по кодовым точкам — сразу.

Тот же дамп показал ещё две особенности панели Прайма. Справа каждая строка несёт
невидимый хвост из `§` и служебного символа — так сервер делает строки уникальными;
в число он не попадает, потому что класс захвата обрывается на `§`, и это закреплено
тестом. А записи приходят по возрастанию счёта, то есть снизу вверх, поэтому мод
сортирует их как ванильный HUD — по убыванию и не больше пятнадцати.

## Структура

```
src/main/java/dev/yebatop/holyhelper/   код мода
src/main/resources/holyhelper/          patterns.json
src/test/java/                          тесты разбора на реальных строках
design/                                 макеты интерфейса
scripts/                                вспомогательные скрипты
```

Макеты интерфейса лежат в [`design/`](design/) — там же описано, как они устроены
и что выяснилось при сверке с игрой.
